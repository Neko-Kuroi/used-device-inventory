# 使い方 ― used-device-inventory

中古のスマートフォンとパソコンを、1台ごと (個体) に管理する在庫台帳の
使い方です。設計の経緯は PLAN.md、起動方法の要点は README.md にあります。

## 1. 最初の1回だけ: 管理者を作る

プログラムを起動してブラウザで開くと、最初は「初期設定」の画面が出ます。
ここで作るユーザーが管理者になります。パスワードは8文字以上です。

- 管理者は、IMEI の全文を見られます。一般ユーザーは末尾4桁だけです。
- 使う人が増えたら、管理者が「ユーザー管理」から追加します。
  管理者にする人にだけ「管理者にする」にチェックを入れます。

## 2. 日々の流れ

1台の端末は、次の順番で進みます。

### (1) 仕入れたら、まず登録する

「新規登録」から、その端末の情報を入れます。

- 必須なのは **シリアル番号** だけです。同じシリアル番号は二重に登録できません。
- 種別 (スマートフォン／パソコン／タブレット)、メーカー、機種名、
  状態ランク (S／A／B／C／ジャンク)、外観メモ、付属品、仕入れ日・
  仕入れ先・仕入れ価格を分かる範囲で入れます。
- 登録した直後の状態は、必ず「仕入済み」になります。

### (2) IMEI は、判別できたものだけ入れる

スマホの場合、IMEI が読めれば入力します (15桁の数字)。

- 読めない・分からない場合は、 **無理に入れず空欄のまま** にしてください。
  その個体は、ネットワーク利用制限が「確認できず」と自動で記録されます。
- IMEI が入っている場合は、通信会社の確認ページで利用制限
  (○／△／×) を確認し、その結果も選んでおきます。
  × の個体は「販売可能」に進めません。
- 利用制限と「確認できず」はスマホの話です。PC とタブレットでは、
  この欄は空欄のまま (対象外) になります。

### (3) 検査する

詳細画面から「チェックリストを開く」を押します。

- 種別ごとに項目が違います (スマホ10項目、PC 11項目、タブレット8項目)。
- 各項目に 合格／不合格／対象外 を入れます。その個体に無い機能
  (生体認証が無い機種など) は「対象外」です。
- **全項目に結果が入り、不合格が1つも無い** ときに「検査完了」になります。
  不合格がある間は、完了にはなりません。整備して直ったら結果を直します。
- 誰が・いつ検査したかは、項目ごとに自動で残ります。

### (4) データ消去を記録する

中古端末では必須の記録です。編集画面の「検査・データ消去」の欄に、
消去した日と方法 (例: 本体の初期化、専用ソフトで消去) を入れます。
記録した人も自動で残ります。

### (5) 状態を進める

状態の変更は、詳細画面の「状態の変更」からだけ行います
(編集画面からは変えられません)。

- 基本の流れ: 仕入済み → 検査中 → 整備中 → 販売可能 → 取り置き → 販売済み
- 「販売可能」に進めるには、検査完了とデータ消去の記録が必要です。
  足りないものは、変更画面に「不足」として表示されます。
- 基本の流れ (仕入済み → 検査中 → 販売可能 → 販売済み) を戻す・飛ばすとき、
  整備中から検査中に戻すとき、返品・処分にするときは **理由が必須** です。
  理由は履歴に残ります。
- 「処分」は最後の状態です。そこからは戻せません。
- 返品は「販売済み」からだけ入れます。

関門 (販売可能の条件) を守るための仕組みが3つあります。

- **販売可能・取り置きの間は、関門に関わる項目は編集で変えられません**
  (種別、IMEI、ネットワーク利用制限、データ消去の記録)。
  変える必要があるときは、先に状態を戻してから編集してください。
- **販売可能・取り置きの間に検査で不合格が出たら**、状態は自動で
  「検査中」に戻ります。履歴に「自動で戻しました」と残ります。
- **返品になったら、検査結果とデータ消去の記録はリセットされます**。
  返品された端末は中身が変わっているかもしれないためです。
  再び売るには、検査とデータ消去をやり直してください。

あわせて、**種別を変えると検査結果はリセットされます**
(種別ごとに検査項目が違うため)。

### (6) お金がかかったら、経費に入れる

詳細画面の「経費と粗利」から、その1台のためにかかったお金を
項目ごとに追加します (日付、種類、金額、備考)。

- 種類は 部品代／送料／販売手数料／その他 です。全部が粗利の計算に効きます。
- 粗利は **実売価格 − 仕入れ価格 − 経費の合計** で、詳細と一覧に出ます。
  まだ売れていない個体は、販売予定価格での「予定粗利」が目安になります。
- 売れたら、編集画面で販売日・販売先・実売価格を入れてください。
  実売価格か仕入れ価格が無い個体は、粗利は出ません (「―」表示)。

### (7) 写真を付ける

詳細画面の「写真」から、その個体の写真を追加できます。

- 種別は 正面／背面／傷／その他 の4種です。
- 1台あたり5枚まで、1枚5MBまで、形式は JPEG／PNG／WebP だけです
  (拡張子と中身の両方を確かめます)。
- iPhone の写真は、ふつうは送るときに JPEG に変換されます。
  名前が .HEIC のままでも、中身が変換済みの JPEG なら受け付けます。
  変換されずに HEIC のまま届いた写真は受け付けられません
  (その旨の表示が出ます)。その場合は、写真を JPEG に変換してから
  送り直してください。
- 写真は小さい画像で並び、クリックすると実物が開きます。
  削除すると、記録と実ファイルの両方が消えます。
- 追加と削除は履歴に残ります。販売可能・取り置きの間でも、
  写真の追加と削除はできます。
- 一覧には「写真 N枚」とだけ出ます。

### (8) 一覧と CSV

- 一覧では、言葉での検索と、種別・状態での絞り込みができます。
- 「CSVでダウンロード」は、今の絞り込みのまま CSV を出します。
  IMEI は末尾4桁だけです。全文は CSV には出ません。

## 3. 履歴について

登録・編集・状態の変更・検査・経費の追加と削除は、すべて詳細画面の
「履歴」に残ります (いつ、誰が、何をしたか)。間違えたときは、
まず履歴を見ると経緯が分かります。

## 4. 運用の注意

- ホストのパソコンが止まっている間は、他の端末からは使えません。
- データベースは `instance/devices.db` です。このファイルを、
  ホスト以外の場所にも定期的にコピーして保管してください。
  写真を使っている場合は、`instance/photos/` フォルダも一緒に
  コピーしてください (写真の実物はそちらに入っています)。
- 一般のインターネットには公開しないでください。アクセスは
  Tailscale 経由だけにします。
- パスワードを忘れたユーザー (管理者を含む) がいる場合は、ホストの
  パソコンで `.venv/bin/python reset_password.py <ユーザー名>` を実行します。
  新しいパスワードを2回入れると、作り直せます。ユーザー名が
  分からないときは、`.venv/bin/python reset_password.py` だけで一覧が出ます。
  (画面からの再設定は今のところありません。ホストのパソコンを
  操作できる人だけが使える方法です。)
